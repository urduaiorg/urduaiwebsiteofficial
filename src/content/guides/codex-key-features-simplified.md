کوڈیکس کو صحیح سمجھنے کے لیے اس کے چند بنیادی الفاظ سمجھنا بہت ضروری ہے۔ اچھی بات یہ ہے کہ یہ سب technical لگتے ضرور ہیں، لیکن اصل میں ان کا مطلب بہت سادہ ہے۔

اس گائیڈ میں ہم وہی terms سمجھیں گے جو ابتدائی صارفین کو سب سے زیادہ confuse کرتی ہیں۔

## اسکل کیا ہوتی ہے؟

اسکل کو سادہ لفظوں میں **تیار شدہ کام کرنے کا طریقہ** سمجھیں۔

مثلاً اگر کوڈیکس (Codex) کے پاس presentation بنانے کی skill ہو تو اسے پہلے سے پتا ہوتا ہے کہ:

- سلائیڈ structure کیسے بنانا ہے
- headings کیسے لکھنی ہیں
- editable deck کیسے تیار کرنا ہے
- آخری نتیجہ کیسے verify کرنا ہے

یعنی skill، کوڈیکس کو smarter ورک فلو دیتی ہے۔

## پلگ اِن کیا ہوتا ہے؟

پلگ اِن ایک ایسا add-on ہے جو کوڈیکس کو extra طاقت دیتا ہے۔

مثلاً:

- گٹ ہب plugin
- گوگل ڈرائیو plugin
- کلاوڈ فلیئر plugin

اگر skill "کام کرنے کا طریقہ" ہے تو plugin "extra tool" ہے۔

## سیاق و سباق کیا ہوتا ہے؟

سیاق و سباق کا مطلب ہے وہ ساری relevant information جو کوڈیکس کے پاس موجود ہو۔

مثلاً:

- آپ نے کیا کہا
- کون سی فائلز پروجیکٹ میں ہیں
- اس وقت کون سا کام چل رہا ہے
- پچھلی instructions کیا تھیں

اگر context واضح ہو تو کوڈیکس بہتر کام کرتا ہے۔ اگر context کم ہو تو وہ guess زیادہ کرتا ہے۔

## ورک اسپیس کیا ہے؟

ورک اسپیس وہ جگہ ہے جہاں آپ کے پروجیکٹ کی فائلز ہوتی ہیں۔

یہی وہ جگہ ہے جہاں کوڈیکس:

- فائل پڑھتا ہے
- فائل بناتا ہے
- فائل ایڈٹ کرتا ہے
- پروجیکٹ run کرتا ہے

اسے اپنے "کام کے کمرے" کی طرح سمجھیں۔

## پرامپٹ کیا ہوتا ہے؟

پرامپٹ وہ instruction ہے جو آپ کوڈیکس کو دیتے ہیں۔

مثلاً:

> میرے لیے ایک Urdu لینڈنگ پیج بنا دو
> اس دستاویز کو زیادہ پیشہ ورانہ لہجہ میں لکھ دو
> اس ایپ کی mobile layout ٹھیک کر دو

بہترین پرامپٹ وہ ہے جس میں مقصد، انداز، اور required نتیجہ واضح ہو۔

## تھریڈ کیا ہوتا ہے؟

تھریڈ ایک جاری conversation یا work session ہوتا ہے۔

سادہ الفاظ میں:

- ایک thread = ایک کام یا ایک پروجیکٹ کی گفتگو

اگر آپ ایک ہی thread میں کام جاری رکھتے ہیں تو کوڈیکس کو continuity ملتی ہے اور وہ کم confuse ہوتا ہے۔

## منصوبہ کیا ہوتا ہے؟

کبھی کوڈیکس پہلے plan بناتا ہے اور پھر کام کرتا ہے۔ یہ خاص طور پر مفید ہوتا ہے جب پروجیکٹ بڑا ہو۔

مثلاً:

1. پہلے فائلز دیکھنا
2. پھر structure سمجھنا
3. پھر content add کرنا
4. پھر test کرنا

یہ plan آپ کو بھی clarity دیتا ہے۔

## منظوری کیا ہوتا ہے؟

کچھ کام ایسے ہوتے ہیں جو کوڈیکس ہر بار خود نہیں کر سکتا، خاص طور پر sensitive کام:

- risky command
- major delete
- external system action

ایسے cases میں approval درکار ہو سکتی ہے۔ یعنی پہلے user کی اجازت۔

## سینڈ باکس کیا ہوتا ہے؟

سینڈ باکس ایک safety boundary ہے۔

سادہ مثال:

- کوڈیکس کو کہاں تک access ہے؟
- کون سی فائلز تک رسائی ہے؟
- کیا internet allowed ہے؟

یہ rules safety کے لیے ہوتے ہیں۔

## ہک کیا ہوتا ہے؟

ہک ایک automatic rule ہوتا ہے جو کسی خاص وقت پر چلتا ہے۔

مثلاً:

- فائل ایڈٹ سے پہلے check
- command کے بعد validation

عام user کو hooks بنانا ضروری نہیں، لیکن advanced teams یہ استعمال کرتی ہیں۔

## ایم سی پی کیا ہے؟

ایم سی پی ایک bridge ہے جس کے ذریعے کوڈیکس دوسری systems سے جڑتا ہے۔

عام user کے لیے اتنا سمجھنا کافی ہے:

- اگر کوڈیکس کو کسی external tool سے بات کرنی ہو
- یا کسی live service سے data لینا ہو

تو MCP جیسے systems کام آتے ہیں۔

## براؤزر کیا کرتا ہے؟

اگر آپ ویب سائٹ یا ایپ بنا رہے ہیں تو browser preview بہت اہم ہے۔ کوڈیکس اس preview کو کھول کر check کر سکتا ہے:

- page کھل رہا ہے یا نہیں
- لے آؤٹ ٹوٹ تو نہیں رہا
- button کام کر رہا ہے یا نہیں

یہ ابتدائی صارفین کے لیے بہت helpful ہے کیونکہ صرف code دیکھنے سے مسئلہ ہمیشہ واضح نہیں ہوتا۔

## جائزہ کیا ہوتا ہے؟

جائزہ کا مطلب ہے کوڈیکس changes کو check کرے:

- بگ تو نہیں؟
- risk تو نہیں؟
- کچھ ٹوٹ تو نہیں گیا؟

یعنی صرف بنانا نہیں، verify بھی کرنا۔

## ابتدائی صارفین کے لیے سب سے اہم کون سی چیزیں ہیں؟

اگر آپ نئے ہیں تو شروع میں بس یہ terms اچھی طرح سمجھ لیں:

- پرامپٹ
- سیاق و سباق
- ورک اسپیس
- تھریڈ
- اسکل
- پلگ اِن

باقی چیزیں آہستہ آہستہ واضح ہو جائیں گی۔

## ایک یاد رکھنے والا formula

کوڈیکس کے ساتھ کام کو یوں سمجھیں:

- `پرامپٹ` = آپ کیا کہہ رہے ہیں
- `سیاق و سباق` = کوڈیکس کیا جانتا ہے
- `ورک اسپیس` = کوڈیکس کہاں کام کر رہا ہے
- `اسکل` = کوڈیکس یہ کام کیسے بہتر کرے گا
- `پلگ اِن` = کوڈیکس کے پاس extra tool کون سا ہے

یہ پانچ چیزیں واضح ہوں تو زیادہ تر ابتدائی صارف problems حل ہو جاتی ہیں۔

## ابھی آپ کو کیا کرنا چاہیے؟

اب جب یہ بنیادی الفاظ واضح ہو گئے ہیں، تو اگلا قدم یہ ہونا چاہیے کہ کوڈیکس سے کوئی آسان عملی نتیجہ بنوایا جائے، جیسے:

- دستاویز
- سلائیڈ
- ہینڈ آؤٹ
- ویب صفحہ

اسی سے اصل learning شروع ہوتی ہے۔
